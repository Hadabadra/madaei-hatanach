# משימה: מיון וניקוי כפילויות בתוכן הממתין, ושילוב מהיר

**רקע**: ריפו `madaei-hatanach` (https://github.com/Hadabadra/madaei-hatanach).
כל התוכן הגולמי ב-`docs/תוכן-ממתין-25-08-26/` (ר' README.md שם לפירוט מלא
של כל קובץ) — **חוץ מ-`צבעים.txt` שכבר שולב** (29 ערכים ב-`guides/domem/data/domem-data.js`,
קטגוריה `colors`).

## מה המשתמש ביקש (הכי חשוב ראשון)

1. **עדיפות עליונה: קבצי "ערך-היום-מאורעות-1.txt" עד "4.txt".** אותו מבנה
   כמו `TANAKH_DATE_EVENTS` ב-`guides/_shared/dates.js` (day/month/event/source/
   quote/explanation). **חשד כפילות חזק גם בין 4 הקבצים עצמם וגם מול
   dates.js הקיים** (כולל מול ~40 מאורעות שנוספו ב-25/08/26).
2. קבצי "כלים-מהמקורות-1.txt" עד "5.txt" — רשימות כלים מהתנ״ך/משנה/תלמוד,
   חשד כפילות חזק בין הקבצים (1 ו-3 חופפים כמעט לגמרי, יש שיבושי OCR
   בחלקם - למשל `"ב me'"` במקום `"ב'"`).
3. "מטבעות.txt" — טבלת מטבעות/משקלות. יש כבר קטגוריית `coins` קיימת
   ב-domem-data.js (ריקה/כמעט ריקה) שמתאימה.
4. "השלמת-ערכים-מורחבת-פי-22.docx" — קובץ Word, לא חולץ טקסט ממנו עדיין.
   חופף תמטית לקבצי הכלים.
5. **"והחיות"** — לבדוק אם משהו מתוך התוכן הגולמי (בעיקר קבצי הכלים)
   שייך בפועל למדריך "בע״ח" (`guides/animal/data/`) ולא ל"דומם" - טרם
   נבדק כלל.

## איך לעבוד (הוראה מפורשת מהמשתמש)

**לכתוב ולהריץ סקריפט מיון/דה-דופ ישירות, בלי בדיקות מקדימות מיותרות.**
המשתמש לא רוצה ניתוח ארוך - רוצה תוצאה מהירה. הגישה שהוכיחה את עצמה
הערב (26/08, ר' `guides/domem/data/domem-data.js` commit של הצבעים):

1. סקריפט Node שקורא כל קובץ מקור (CSV בתוך .txt, פרסור ידני עם תמיכה
   ב-quoted fields).
2. **דה-דופ בתוך כל קבוצת קבצים** (המאורעות בינם לבין עצמם, הכלים בינם
   לבין עצמם) - לפי שם/תאריך זהה, לא רק טקסט זהה מילה-במילה.
3. **דה-דופ מול הדאטה הקיים** בקוד (`TANAKH_DATE_EVENTS` ב-dates.js לגבי
   מאורעות; `DATA` ב-domem-data.js לגבי כלים/מטבעות) - לפי `day`+`month`
   למאורעות, לפי `name` לכלים/מטבעות.
4. הפלט: רק הרשומות החדשות-בפועל, בפורמט JS מוכן להדבקה.
5. **לשלב בפועל בקבצים**, לא רק לדווח - בדיוק כמו שנעשה עם הצבעים.

## מלכודות ידועות (מהערב, אל תחזרו עליהן)

- **קובץ ה-DATA הראשי (`domem-data.js`) הוא שורה אחת ענקית** (~900K תווים) -
  אין להשתמש ב-`node -e` עם הקובץ מוטמע בפקודה (חורג ממגבלת אורך הפקודה
  ב-Windows/git-bash). לקרוא/לכתוב עם קובץ סקריפט (`node script.js`), לא
  `node -e "..."`.
- **דומם דורש שדות חובה לא-ריקים** לכל ערך: `explanation` ו-`identification`
  חייבים תוכן (הוולידטור גוזר "שדה חובה" מ-100% מילוי בדאטה הקיים - ריק
  = רגרסיה שנתפסת ומעכבת שחרור). לוודא לפני commit, לא אחרי.
- **הפרדת סוגריים בעריכת מחרוזת ה-DATA**: הקצה של השורה הוא `}];` (סוגר
  ערך + סוגר מערך + נקודה-פסיק) - `slice(0,-2)` מסיר רק `];` ומשאיר את
  ה-`}` האחרון של הערך הקודם. `slice(0,-3)` (טעות שקרתה כבר) מוחק תו
  אחד יותר מדי ושובר את ה-JSON.
- **לבדוק syntax אחרי כל עריכה**: `node --check <file>` על כל קובץ שנערך.
- **להריץ `node tools/validate.js --strict`** אחרי שילוב ולוודא ש"שדות
  חובה חסרים" נשאר 0 (לא רק שהקובץ תקין syntactically).
- **גרסה הבאה**: לבדוק `git tag --list` לפני שקובעים מספר (אסור לארוז
  שוב תחת תג קיים - כלל קבוע בפרויקט, ר' `CLAUDE.md`).
- לזרום workflow המלא: commit → `build/pack.ps1 -AllowValidationErrors -Release`
  (או שני שלבים אם `-NoBump` נדרש) → `git push origin <branch>:main` +
  `git push origin v<version>` (לא `git push` סתם - שם הענף המקומי לא
  תמיד תואם `main`).
